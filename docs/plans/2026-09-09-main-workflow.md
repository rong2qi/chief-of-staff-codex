## 已确认决策
- DIRECT 是执行方式，不是角色。Chief 默认自行高效执行，委派必须有收益，优先复用现有执行者并保留唯一写入责任。
- 当前工作决定发现深度：明确操作/修复直接执行；技术未知针对性调查；新产品完整发现；重大变化补受影响部分。
- 低风险证据充分可自检，高风险认证/权限/资金/迁移/不可逆必须独立复核。连续两轮无进展转独立诊断。
- 有限预算由 Chief 根据用户约束、历史和资源设定。同一工作换人/阶段/候选/编号不清零。
- main 使用通用内存/CPU/压力语言，不使用机型专用规则。重任务受控、无冲突轻任务继续；未知资源默认一个重任务。
- 原 Chief 明确采用一次：预览、冲突检查、事务写入、幂等和失败恢复，保留身份/历史/授权。旧项目不自动升级，新项目默认新版。
- 同步规则和真实校验器；不构建后台自动进程调度器。
- static-first，生成产物先保留再校验。构建/验证/发布资格分开；关键失败禁止发布但保留产物。APK-only 不涉及 AAB。
- 保留既有项目完整性、安全、授权和失败记录，不以当前工作标签绕过未决产品要求。
