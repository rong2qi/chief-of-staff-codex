# Chief v2.0.2 execution contract

## Goal and evidence

Repair v2.0.x Testing over-blocking, repeated validation, telemetry preemption,
and lost evidence inheritance without adding a second Testing system. The base is
the authenticated `v2.0.1` tag commit `a18d180a050bffecaae7a7346d771aaf247234d6`.
Its Python 3.12.14 baseline ran 362 tests: 361 passed, one optional test skipped,
zero failed.

## Scope and constraints

The sole write surface is the isolated `release/v2.0.2` worktree. In scope are
Chief policy text, the v2.0.1 evidence implementation, a cheap control layer,
regression/dogfood fixtures, version metadata and fixed-source sync support.
Business repositories, APK/AAB execution, fleet adoption and production actions
are outside scope. Preserve project schema 2, V1 frozen evidence readability,
artifact preservation, native Testing authority, user changes and Git history.
No force push or tag rewrite.

## Acceptance

- Telemetry is record-only and cannot preempt implementer/build/user events.
- Evidence is inherited until an observed input/dependency/risk invalidates it.
- Testing requests require `TESTING_JUSTIFICATION` and contain only delta scope.
- L0 is deterministic/local; L1 defaults local; L2 is targeted/non-blocking;
  L3 or explicit synchronous policy blocks only its dangerous action.
- One delivery gets one automatic retry; infra error is not product failure.
- Testing pending permits unrelated modules and creative iterations to continue.
- APK-only artifact preservation and gate separation remain covered.
- Five incident fixtures show the old wait/retest behavior and the new result.
- Targeted tests, full regression, version/tag identity and remote main/tag
  equality pass before release is declared complete.

## Checks

Run the targeted control/evidence/sync/build suites, the dogfood CLI, skill quick
validation, the complete unittest discovery, `git diff --check`, and independent
read-only review of the exact frozen candidate. Promotion occurs only after that
evidence is complete and the existing Testing authority returns a verdict for
the exact candidate.

Observed validation after repair cycle 1: targeted 78/78 passed; full regression
ran 385 tests with 384 passed, one existing optional skip and zero failures. R1
`75ba4b8fd75196b8acb879963f4e83431495e104` remains failed because it accepted
PASS/FAIL status without delivery items. Repair cycle 1 adds the 23rd regression
and requires a nonempty items list for a verdict. The Skill
validator itself could not import its external
PyYAML dependency, so its exact run remains unavailable and is disclosed in the
release notes rather than silently treated as PASS.
