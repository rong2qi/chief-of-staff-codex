The candidate digest uses `CHIEF_V3_CANDIDATE_V1` framing. It enumerates the
union of `git diff --name-only -z --no-renames <baseline>` and
`git ls-files --others --exclude-standard -z`, then sorts paths by UTF-8 bytes,
and hashes, for each path, the eight-byte big-endian path length, path bytes,
eight-byte content length, and current file bytes. A deleted path would use the
literal bytes `<DELETED>`. Before hashing this report, the value between
backticks on its `candidate_digest` line is replaced with `SELF_NORMALIZED`.
Ignored caches, `.git`, and temporary test repositories are not candidate
files. This normalization makes the recorded value reproducible without
excluding the report itself.

## Host abilities and unresolved limits

Exercised host abilities are local filesystem read/write, real Git init/add/
commit/show/diff/ref observation inside disposable repositories, subprocess
execution of the user path, and SHA-256 validation. The Goal Loop module itself
performs none of those effects: it returns a bounded intent and validates
caller-supplied fresh observations. A real host tool or command must perform and
observe every effect.

Unresolved limitations:

- the historical architecture remote/commit could not be read anonymously in
  this environment and must be revalidated when credentials or access change;
- a pre-integration source checkout cannot use its baseline Git commit as the
  candidate identity, so this report binds a deterministic content digest;
- `quick_validate.py` remains unavailable until its own runtime has PyYAML;
- no live Codex task, automation, external Testing Chief, business project,
  browser UI, install, or release path was exercised by this local source test.
