# Bundle schema

Each new lineage migration has numbered directories containing `manifest.json`, `handoff.md`, `artifacts.json`, `automations.json`, and `transcript-ref.json`. Historical schema-v1 bundles remain checksum-verifiable but cannot establish automation parity.

The manifest records schema version, lineage/migration number, status, predecessor/successor IDs, title, cwd/project, model, context sample, source session hash, Git snapshot, global instruction hash and salutation, automation-binding count, file checksums, parity/takeover state, and UTC timestamps. Status is `checkpoint_ready`, `successor_created`, `verified`, `migration_blocked`, or `needs_attention`; never mark verified before handshake parity.

`artifacts.json` is an object of stable file/commit/branch/task/approval/report/link/check references without secrets. `transcript-ref.json` contains only the immutable predecessor session path, hash, size, time, and thread ID.

`automations.json` is an array. Every record contains exactly `id`, `name`, `kind`, `target_thread_id`, `status`, `schedule`, `prompt_sha256`, and `notification_policy`. IDs are unique. Same duty is the canonical tuple of name, kind, canonical-JSON schedule, prompt SHA-256, and notification policy; target and runtime ID are excluded so rebinding remains the same duty. Two ACTIVE records may not share that fingerprint. Different intentional schedules are different duties. An empty array is accepted only with a timestamped live query scoped to the exact predecessor target and every recorded ID.

`verify-migration` accepts an explicit live snapshot with `evidence_kind: live_automation_view`, `observed_at`, `query_scope: predecessor_target_and_recorded_ids`, exact queried predecessor/recorded IDs, existing-authorization evidence, `automations`, and `absent_automation_ids`. A changed ID is allowed only when the old exact ID appears in the live absence list, existing authorization permits one minimal equivalent, and that equivalent is unique. Applicable pin parity requires a separate timestamped `live_list_threads` evidence object with the exact successor ID in `pinned_thread_ids`; a Boolean or operation receipt cannot satisfy it. The result is `MIGRATION_READY` only when bundle, automation, and applicable pin parity pass; otherwise it is `MIGRATION_BLOCKED` with `automation_rebind_failed` and `keep_predecessor_active_unarchived: true`. Historical repair returns `REPAIR_VERIFIED` and preserves the predecessor's archived state.
