# Rollover protocol

1. Re-read the newest token event. Continue rollover only at 85% or above, at a safe boundary, with write owners identified.
2. Capture exact IDs and distinguish facts, inference, questions, unsuccessful attempts, approvals, active roles, Git state, tests, risks, and the next action. Reference the immutable session by path and SHA-256 instead of copying it into the prompt. Inventory every task-bound automation with exact ID, name, kind, target task ID, status, schedule, prompt SHA-256, and notification policy.
3. Run `capture --safe-boundary-id <stable-id>` to fresh-sample the latest nonzero usage, choose the next unused monotonic number, build atomically, and verify immediately. A complete source-task safe boundary permits at most one build+verify attempt; do not sleep, poll, or loop.
4. Prefer a clean task in the same saved project using the proven working-tree state. A same-history fork preserves continuity but is not a clean context reset.
5. Require a core bundle parity candidate. Pending approvals stay pending, children keep their Chief/phase, and write ownership does not change merely because the conversation changes. Do not emit final `MIGRATION_READY` yet.
6. Before takeover, authority switching, or predecessor archival, reuse each bound automation and rebind it to the exact successor task ID. Only live absence plus existing authorization permits exactly one minimal equivalent. Preserve schedule, prompt semantics/hash, notification policy, status, and scope; duplicate ACTIVE same-duty automations are forbidden.
7. Require a fresh, timestamped live automation view scoped to the exact predecessor target and recorded IDs; references and update receipts are not proof. Then pin the successor when applicable and require fresh exact-ID `list_threads` evidence.
8. Emit final `MIGRATION_READY` only after bundle parity, automation parity, and applicable pin parity all pass. Any mismatch records `automation_rebind_failed`, returns `MIGRATION_BLOCKED`, and keeps the predecessor active and unarchived. After readiness, switch authority, leave a redirect, and archive the predecessor. For historical repair after archival, never unarchive/delete the predecessor or duplicate the task/automation.

## Automatic transient capture continuation

Only two failures are capture-transient: exact `source session changed after capture`, and a target migration number already existing (`File exists`) when the operation has no overwrite, deletion, or content-drift intent. A number collision is skipped under the lineage lock; a changed source schedules one automatic attempt at a later safe boundary. Every attempt uses a new monotonic number and preserves all older bundles byte-for-byte.

Before each later attempt, fresh-read the newest nonzero token sample, threshold, destination write access, disk/storage safety, worktree continuity, ownership, and pending approvals. Below 75%, cancel the stale checkpoint trigger. At 75%–<85%, create or refresh only a checkpoint. At 85% or above, a successor remains forbidden until a valid bundle exists. Transient capture continuation never creates, pins, rebinds, switches authority, archives, or deletes a task.

After three consecutive transient failures, stop bundle writes and enter Chief-owned read-only diagnosis/backoff without `USER_ACTION_REQUIRED` or a TODO item. Resume only at another safe boundary after evidence supports the same narrow transient class. A new permission need, safety or data risk, unproven dirty-worktree continuity, persistent storage risk, non-transient verification defect, or any automation/pin/bundle parity mismatch is not transient and follows its existing approval or fail-closed rule.

This is automatic authorization, not an infinite retry loop: repeated capture can create directories, consume disk and I/O, and mutate the source session enough to self-trigger another mismatch while hiding permission, storage, validation, worktree, or parity defects. The one-attempt-per-boundary rule, fresh checks, new numbers, and explicit diagnosis conditions prevent that failure mode.
