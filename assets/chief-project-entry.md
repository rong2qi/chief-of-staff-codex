# Chief of Staff project entry

Chief is the single source of generic behavior. Verify the installed
`chief-of-staff` checkout against `.chief-of-staff/chief-lock.json`; a repository
mentioned in a brief, log, or reference packet is not the Chief source or the
delivery host. Use the pin or perform an explicitly authorized sync—never
silently follow floating main.

For current work, read the pinned source's `SKILL.md` first and run its Goal
Record + Next Action Loop. Load `references/work-execution.md` only when the
selected action needs v2 admission, attempt budgets, retries, resource/build
rules, explicit adoption, or compatibility. Load every other reference only at
the observable trigger named by `SKILL.md`.

Read `.chief-of-staff/project-overrides.md` when present. It may add stricter
project commands or constraints, but cannot expand permission, change generic
authority, erase failures, or waive validation.

Use `scripts/chief_sync.py` only for explicit project or fleet migration,
preview, or rollback. A sync does not run business work or grant commit, push,
release, deployment, production, deletion, external-send, or permission effects.
Continue the registered Chief task; do not create another Chief merely to adopt
the source.
